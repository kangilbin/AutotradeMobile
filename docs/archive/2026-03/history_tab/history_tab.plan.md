# Plan: history_tab (화면 분리 리팩토링)

## 1. 배경 및 목표

현재 `HistoryTab`에 차트 + 통계 + 거래 내역이 모두 한 화면에 있어 사용자가 확인하기 어려움.
화면 역할을 명확히 분리하여 UX를 개선한다.

## 2. 요구사항

### 2.1 ChartTab 개선
- HistoryTab에 있는 차트(StockChart) + 범례 + 로딩 오버레이를 ChartTab으로 이동
- 거래 통계(총거래/매수/매도)를 ChartTab에 표시
- **통계는 전체 총 건수** (기간 필터 아님, `trades` 전체 기준)
- 기존 ChartTab의 더미 데이터 제거, 실제 API 데이터 사용
- `useTradeHistory` 훅을 ChartTab에서 사용

### 2.2 HistoryTab 간소화
- 차트, 범례, 통계 UI 모두 제거
- **거래 내역 리스트만** 표시
- 차트 연동 로직(webViewRef, isSyncFromChart, isSyncFromList, 차트↔리스트 동기화) 제거

### 2.3 TradeHistoryItem 매매 사유(reason) UI 개선
- 현재: `reasons.join(', ')`로 한 줄에 모두 표시
- 변경: **펼치기/접기(Expandable)** 방식으로 표시
  - 기본 상태: 사유 숨김 (카드에 "사유 보기" 버튼 or 아이콘)
  - 펼침 상태: 각 사유를 개별 항목으로 이쁘게 표시 (불릿/태그 스타일)
  - 애니메이션: LayoutAnimation 또는 간단한 높이 토글

## 3. 영향 범위

| 파일 | 변경 |
|------|------|
| `components/swing/ChartTab.tsx` | 전면 리작성 (차트+통계) |
| `components/swing/HistoryTab.tsx` | 차트/통계 제거, 리스트만 유지 |
| `components/swing/TradeHistoryItem.tsx` | reason 펼치기/접기 UI |
| `hooks/useTradeHistory.ts` | 변경 없음 (ChartTab에서 import) |
| `types/tradeHistory.ts` | 변경 없음 |

## 4. 데이터 흐름

### 현재
```
HistoryTab → useTradeHistory() → 차트 + 통계 + 거래 리스트
ChartTab → 더미 데이터
```

### 변경 후
```
ChartTab → useTradeHistory() → 차트 + 범례 + 통계(전체 건수)
HistoryTab → useTradeHistory() → 거래 리스트만 (trades 전체, 필터 없음)
```

> 참고: 두 탭이 각각 `useTradeHistory(swingId)`를 호출하므로 데이터가 2번 fetch됨.
> 현재 단계에서는 수용 가능. 추후 필요 시 부모에서 공유하도록 리팩토링.

## 6. 구현 우선순위

1. **ChartTab 리작성** - 차트 + 범례 + 통계 이동
2. **HistoryTab 간소화** - 차트/통계/동기화 로직 제거
3. **TradeHistoryItem reason UI** - 펼치기/접기 구현

## 7. 제외 사항 (YAGNI)

- 두 탭 간 데이터 공유 최적화 (현재 개별 fetch 수용)
- 차트↔리스트 동기화 (ChartTab과 HistoryTab이 분리되므로 불필요)
- 거래 내역 필터링/검색 기능
